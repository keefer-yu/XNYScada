# 流程引擎

流程以 JSON 保存，模型是 `FlowDocument`。一个已发布版本对应一份不可变文档。修改已发布流程时新建版本，发布后运行时在该流程空闲时热切换。

## 文档字段

| 字段 | 含义 |
| --- | --- |
| `Code` / `Name` | 流程编码与名称。触发、子流程按编码引用 |
| `Version` | 版本号 |
| `Station` | 默认工位，决定工位变量的作用域。触发器可以覆盖 |
| `Concurrency` | `Skip` 运行中再次触发则忽略；`Queue` 排队；`Parallel` 允许多实例 |
| `TimeoutMs` | 整次运行超时，0 表示不限制 |
| `StartNodeId` | 入口节点 |
| `Triggers` | 触发器列表 |
| `Variables` | 变量声明 |
| `Nodes` / `Edges` | 节点与连线。节点坐标 `X`/`Y` 只给设计器使用 |

连线的 `Port` 是离开源节点的端口。常用名称集中在 `Ports`：`next`、`true`、`false`、`ok`、`ng`、`timeout`、`error`、`default`、`body`、`done`、`yes`、`no`、`offline`。Switch 的匹配端口写成 `case:值`。

## 触发器

| 类型 | 用途 | 关键字段 |
| --- | --- | --- |
| `TagRisingEdge` / `TagFallingEdge` / `TagChanged` | 点位边沿或变化 | `Tag` 为点位全名，可用 `Condition` 再过滤 |
| `Timer` | 周期触发 | `IntervalMs` |
| `Manual` | 界面或 API 手动触发 | |
| `MesCallback` | MES 回调 | `Source` 为回调路径 |
| `FlowCompleted` | 另一个流程成功结束后触发 | `Source` 为来源流程编码 |
| `Startup` | 引擎启动时执行一次 | |

`Enabled` 为 false 的触发器不参与运行。

## 变量

| 作用域 | 生命周期 |
| --- | --- |
| `Instance` | 只在这一次运行中有效 |
| `Station` | 同一工位的后续实例仍可读取 |
| `Global` | 引擎内全局保留 |

节点通过表达式读写这些变量，也可以用 `{Tag:设备.点位}` 直接引用实时值，用 `{Recipe:参数名}` 引用当前配方参数。

## 内置节点

节点类标注 `[FlowNode]`。`NodeRegistry` 扫描流程程序集和 `plugins`，设计器与执行器使用同一份描述。脚本节点额外要求 `Flow.Script` 权限。

### 通讯

| 类型 | 名称 | 端口 | 说明 |
| --- | --- | --- | --- |
| `ReadTag` | 读点位 | `next` | 读一个点位到变量 |
| `ReadTags` | 批量读点位 | `next` | 每行 `变量 = 点位全名` |
| `WriteTag` | 写点位 | `next` | 把表达式结果写入 PLC |
| `WriteTags` | 批量写点位 | `next` | 每行 `点位全名 = 值表达式`，按顺序写 |
| `WaitSignal` | 等待信号 | `next` / `timeout` | 轮询直到条件成立或超时 |
| `Handshake` | PLC 握手完成 | `next` / `timeout` | 置完成位，等 PLC 清请求位后再复位完成位 |

### 逻辑

| 类型 | 名称 | 端口 | 说明 |
| --- | --- | --- | --- |
| `Start` | 开始 | `next` | 可选入口 |
| `End` | 结束 | 无 | 可标记本次失败 |
| `Condition` | 条件分支 | `true` / `false` | |
| `Switch` | 多路分支 | `case:*` / `default` | |
| `Loop` | 计数循环 | `body` / `done` | `body` 末端连回本节点 |
| `Delay` | 延时 | `next` | |
| `SetVariable` | 变量赋值 | `next` | 每行 `变量 = 表达式` |
| `Log` | 日志 | `next` | |
| `SubFlow` | 子流程 | `next` / `error` | 调用已发布流程，传入变量副本 |
| `Parallel` | 并行子流程 | `next` / `error` | 同时运行多个子流程并等待全部结束 |

### 业务

| 类型 | 名称 | 端口 | 说明 |
| --- | --- | --- | --- |
| `ScanBarcode` | 扫码 | `ok` / `ng` | 可触发扫码枪，从点位读条码并校验，失败可重试 |
| `BarcodeCheck` | 条码校验 | `ok` / `ng` | 校验格式、长度、重码、是否已绑托盘 |
| `BindTray` | 电芯绑定托盘 | `ok` / `ng` | 输出 `TrayCellCount`、`TrayFull` |
| `CompleteTray` | 托盘完成 | `next` | 标记满盘或完成 |
| `LoadTray` | 查询托盘电芯 | `ok` / `ng` | 输出 `TrayCells`、`TrayCellCount`、`Cell_{位置}` |
| `UnbindTray` | 托盘解绑 | `next` | `Position` 为空时整盘解绑，输出 `UnboundCount` |
| `CalcGrade` | 分档计算 | `ok` / `ng` | 按当前配方计算，输出 `BinNo`、`BinName`、`IsNg`、`NgCode` |
| `NgJudge` | NG 判定 | `ok` / `ng` | 按 NG 代码映射料盒，输出 `BoxNo`、`NgCode` |
| `SaveCellRecord` | 保存生产记录 | `next` | 已知字段进主表，其余进扩展字段 |
| `SaveNgRecord` | 保存 NG 记录 | `next` | |
| `MesCall` | 调用 MES | `ok` / `ng` / `offline` | 输出 `{前缀}Success`、`{前缀}Message` 和响应映射字段 |
| `RaiseAlarm` / `ClearAlarm` | 触发 / 清除报警 | `next` | |
| `Confirm` | 人工确认 | `yes` / `no` | 弹窗等待；超时使用默认结果 |

`SaveCellRecord` 识别的字段：`CellCode`、`TrayCode`、`Position`、`Voltage`、`InternalResistance`、`Capacity`、`BinNo`、`BinName`、`IsOk`、`NgCode`。

## 运行与调试

`IFlowEngine` 在启动时加载已发布流程。界面或 `TriggerAsync` 可以按编码手动触发。实例状态包括 `Running`、`Completed`、`Failed`、`Cancelled`、`TimedOut`。

引擎向外报告实例开始/结束和节点开始/结束，流程监控页据此高亮当前节点。`FlowDebugger` 支持单步和模拟运行，对应权限 `Flow.Debug`。
